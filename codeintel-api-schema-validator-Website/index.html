codeintel-api-schema-validator

The Pattern Shop. A command line validator that loads one data document and judges it against one JSON Schema, and refuses the judging entirely when the schema handed to it is an OpenAPI document rather than a plain JSON Schema.

The repository main.py
InputTwo required positionals, loaded in order: a data file, then a schema file
JudgementA single jsonschema validate call against the one schema handed to it
SuccessPrints Validation successful! and exits 0
FailureA violation raises the single best matching error and exits 1, as do a missing file and an invalid schema

Usage

python3 main.py DATA_FILE SCHEMA_FILE [--data_type json|yaml] [--schema_type json|yaml] [--log_level LEVEL]

The data and schema types are inferred from the file extensions when the flags are omitted, and the log level defaults to INFO. The two files load in order, so when both are broken the error names the data file.

OptionWhat it does
DATA_FILEThe one document to judge.
SCHEMA_FILEThe one JSON Schema to judge it against.
--data_type / --schema_typejson or yaml; inferred from the file extension when omitted.
--log_levelLogging level. The default is INFO.

The refusal at the centre

  • A schema document carrying a top level openapi or swagger key is rejected with exit 1 and the instruction to pass a plain JSON Schema instead, for example the entry under components/schemas in the OpenAPI document.
  • The refusal exists because jsonschema would otherwise treat the OpenAPI document's unknown keywords as annotations and pass almost anything.
  • The repository's own GitHub description claims validation against OpenAPI or other schema definitions. The code does the opposite, and this site states the code's behaviour.

Requirements

Python with jsonschema 4.17.0 or later and PyYAML 6.0 or later.
